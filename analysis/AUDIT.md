## 1. Критичные ошибки (исправлены)

### 1.1. Абсолютные пути `C:\projects\video\...`

Во всех скриптах был жёстко прописан каталог `C:\projects\video\analysis`, а видео —
`C:\projects\video\drop.mp4`. В этом репозитории (`G:\WebSites\ph\physics_drop`) скрипты
не запускались вообще, хотя README обещал воспроизводимость.

**Исправлено:** все скрипты используют `Path(__file__).resolve().parent`, видео ищется
в `../drop.mp4`, кадры — в `analysis/frames/`.

### 1.2. Время событий считалось по формуле `f / FPS`, а не `(f − 1) / FPS`

В `final_analysis.py` печать моментов удара и вершины использовала `f_hit/FPS`, тогда как
кадр 1 имеет `t = 0`. Это давало сдвиг на 1/30 = 0,033 с:

| Событие | Было в консоли/JSON | Правильно |
|---|---|---|
| Удар 1 | 1,676 с | 1,643 с |
| Вершина | 2,058 с | 2,024 с |
| Удар 2 | 2,439 с | 2,406 с |

В `report.md` и на графиках использовалась правильная формула `(f−1)/FPS`, поэтому
возникало расхождение между отчётом и `params.json`.

**Исправлено:** все моменты событий считаются как `(f−1)/FPS`; в `params.json` записаны
правильные значения.

### 1.3. Дублирование коэффициентов подгонки в четырёх файлах

`cf = (141.3, 3.16, 5.91)` и `cb = (924.8, −41.25, 6.13)` были продублированы в
`final_analysis.py`, `make_report.py`, `make_html.py`, `check_velocity.py`. В одном месте
стояло `3.14`, в другом `3.16`; при пересчёте данные могли разойтись.

**Исправлено:** `final_analysis.py` пишет `params.json`; остальные скрипты читают его.
`make_html.py` подставляет коэффициенты в JS из JSON.

### 1.4. `frames.csv` не содержит `h`, `v` и фазу, хотя README это обещал

README: «frames.csv — покадровая таблица: y, Y, h, v, фаза (109 строк)». На деле в CSV
только `кадр; t_с; y_пикс; Y_см_по_шкале; метод`.

**Исправлено:** README и карточка файла в HTML описывают реальные колонки; `h`, `v` и
фаза по-прежнему вычисляются в HTML и в CSV-скачивании.

### 1.5. HTML-плеер и график не работали на touch-устройствах

На графике стоял `touch-action:none`, но обработчики были только `mousemove`/`click`.
На телефоне клик по графику работал нестабильно, tooltip не появлялся.

**Исправлено:** `pointermove`, `pointerdown`, `pointerleave`; график получил `tabindex`
и управление стрелками.

## 2. Физические и метрологические неточности

### 2.1. Заявленная точность координат ±0,5 см противоречит остаткам подгонки

Подгонка падения по кадрам 32–49 даёт:

* СКО остатков **5,09 px ≈ 0,9 см**;
* максимальный остаток **11,73 px ≈ 2,0 см** (кадр 49);
* стандартная ошибка коэффициента ускорения 0,11 px/кадр² (≈0,17 м/с² без учёта масштаба).

При этом README и отчёт обещали «координаты ±0,5 см». Для резких кадров это ещё
допустимо, для смазанных 41–56 — нет.

**Исправлено:** в отчёте разделены точности: ±0,5 см на резких кадрах, ±1…1,5 см на
смазанных; указаны СКО и максимальный остаток подгонки.

### 2.2. Заявленная точность скорости ±0,1 м/с занижена

Стандартная ошибка скорости у точки удара из подгонки — около ±0,12 м/с, плюс
систематика масштаба ±5 % (≈0,3 м/с). Итог — порядка **±0,3 м/с**, а не ±0,1.

**Исправлено:** в отчёте и README стоит ±0,3 м/с.

### 2.3. Абсолютная высота 1,82 м имела необоснованную точность

Масштаб шкалы меняется примерно на 25 % по длине, а мяч летит в другой плоскости.
Даже после калибровки остаётся систематика порядка ±5 %, то есть **±9 см** по высоте.
При этом отчёт писал «±0,5 см».

**Исправлено:** высота указана как 1,82 ± 0,09 м; отдельно объяснено, что отношение
высот (и e) от общего масштаба почти не зависит.

### 2.4. Объяснение занижения g только сопротивлением воздуха некорректно

Для мяча диаметром 4,1 см при v ≈ 5,9 м/с:

* `A = πd²/4 ≈ 1,32·10⁻³ м²`;
* при `C_d ≈ 0,47`, `ρ = 1,2 кг/м³` сила `F ≈ 0,013 Н`;
* при массе 5 г торможение `a = F/m ≈ 2,6 м/с²`, то есть 26 % от g.

С таким торможением измеренное g было бы около 7 м/с², а не 9,3. Значит, мяч тяжелее
(порядка 20–30 г), либо главная причина — масштаб/перспектива, а не воздух.

**Исправлено:** в отчёте дан количественный расчёт; в HTML добавлен интерактив
«Сопротивление воздуха» с оценкой минимальной массы.

### 2.5. `e = 0,63` по скоростям получено экстраполяцией назад на 7 кадров

Парабола отскока подогнана по кадрам 57–73, а точка удара — кадр 50,3. То есть скорость
сразу после удара (`v↑ = 3,69 м/с`) — экстраполяция на 6,7 кадра назад от первой
измеренной точки (или на 4,7 кадра от опорного кадра 55). Это допустимо, но повышает неопределённость.

**Исправлено:** в отчёте явно сказано, что e по скоростям менее надёжен, чем e по высотам
(0,63 против 0,645). В HTML оба значения показаны.

### 2.6. Калибровка экстраполируется за пределы измеренных меток

Метки: 10…160 см; точка удара — около 179 см по шкале. Квадратичная зависимость
экстраполируется на 19 см вниз. Это ещё один источник систематики, который не был указан.

**Рекомендация:** добавить метки 170–180 см или ограничить калибровку и явно писать
«экстраполяция». В отчёте это отмечено в ограничениях.

### 2.7. «Мяч остаётся на полу» — качественное наблюдение, а не измерение

После кадра 74 мяч уходит с линии шкалы; в `frames.csv` для 74–109 стоит `n/a`.
`meta.json` после ~89-го кадра содержит интерполяцию (значение 456.2 повторяется), а не
реальную координату X. По этим данным нельзя количественно утверждать, что мяч
«остаётся на полу» или что он не подпрыгивает.

**Исправлено:** в отчёте это названо качественным наблюдением; добавлено предупреждение
о частично интерполированном `meta.json`.

### 2.8. «Камера уезжает на 3–4 px» не подтверждено отдельным измерением

В проекте нет файла с оценкой дрожания камеры по фону. Цифра выглядит правдоподобной,
но это оценка, а не результат.

**Исправлено:** в отчёте сказано, что это оценка; рекомендовано измерить дрейф по
неподвижным объектам.

### 2.9. Начальная скорость не строго ноль

Свободный член подгонки `cf[1] = 3,16 px/кадр` соответствует **0,17 м/с** вниз, а не
нулю. Это 3 % от скорости у мата, поэтому модель «отпущен без броска» разумна, но
формулировка «начальная скорость ≈ 0» должна сопровождаться числом.

**Исправлено:** в отчёте указано 0,17 м/с.

### 2.10. Результат g зависит от выбранного диапазона кадров

Подгонка по разным диапазонам даёт:

| Диапазон | g, м/с² |
|---|---|
| 32–49 (использован в отчёте) | 9,33 |
| 33–49 | 9,19 |
| 34–49 | 9,00 |
| 33–47 | 9,62 |
| 34–47 | 9,46 |
| 35–49 | 8,81 |

Разброс ±0,3…0,5 м/с². Это не ошибка сама по себе, но должно быть явно указано:
одно число «9,33» без диапазона создаёт ложную точность.

**Исправлено:** в отчёт добавлен пункт о чувствительности; `params.json` хранит
`fall.range_g`; интерактив «Подгонка параболы» позволяет увидеть остатки.

### 2.11. Формула `h = 1,815 − 4,63·t²` неточна по коэффициенту и теряет v₀

При `g = 9,33 м/с²` коэффициент при `t²` равен `g/2 = 4,665`, а не 4,63. Кроме того,
подгонка даёт начальную скорость 0,17 м/с, поэтому честная формула:
`h = 1,815 − 0,17·t − 4,67·t²`.

**Исправлено:** формула обновлена; коэффициенты лучше генерировать из `params.json`,
чтобы они не расходились с подгонкой.

## 3. Ошибки и улучшения в коде/сборке

### 3.1. Нет `requirements.txt` и явного списка зависимостей

README перечислял `imageio-ffmpeg`, но код его не использовал; `ffmpeg` вызывался
вручную. Не было файла зависимостей.

**Исправлено:** добавлен `requirements.txt` (numpy, pillow, matplotlib); извлечение
кадров автоматически вызывает `ffmpeg` из `PATH`.

### 3.2. Нет понятной ошибки, если кадры не извлечены

`load_frames()` падал на `np.stack([])`.

**Исправлено:** при отсутствии кадров скрипт сам извлекает их из `drop.mp4`; если
`ffmpeg` не найден — понятное сообщение.

### 3.3. Жёстко зашитое разрешение 720×1280

`np.mgrid[0:1280, 0:720]` и координаты 300…1160 ломались бы на другом видео.

**Исправлено:** размеры берутся из `F.shape`; остались только координаты полосы
поиска, привязанные к этому ролику.

### 3.4. Шрифт Arial по absolute path `C:\Windows\Fonts\arial.ttf`

На Linux/macOS скрипт падал.

**Исправлено:** `font()` пробует Arial/DejaVu, затем встроенный шрифт Pillow.

### 3.5. `report.html` генерировался с зашитыми числами

`make_html.py` вручную повторял `cf`, `cb`, `f_hit`, `Y_hit`, `V_IN`, `V_OUT`. Любое
изменение в анализе требовало правки трёх файлов.

**Исправлено:** всё берётся из `params.json`; в JS подставляются значения из Python.

### 3.6. `split_for_server.py` не копировал новые файлы

Скрипт копировал старый список; `params.json`, `school_physics.md`, `AUDIT.md` не попадали
в `deploy/`.

**Исправлено:** список обновлён; пути портируемые.

### 3.7. `meta.py` писал NaN/интерполяцию без пометки

После потери мяча координаты заполнялись `np.interp`, но в JSON не было признака
«это интерполяция». Для маркера это нормально, для физики — нет.

**Исправлено:** `meta.json` теперь содержит `x` и `x_valid` (1 — прямая детекция,
0 — интерполяция). Прямая детекция есть для 68 из 109 кадров; после 74-го кадра
использовать X для количественных выводов нельзя.

### 3.8. HTML: доступность и мобильные устройства

* строки таблицы и пункты хронологии кликабельны, но не фокусируются с клавиатуры;
* у графика не было клавиатурного управления;
* `touch-action:none` без pointer events;
* нет `prefers-reduced-motion`.

**Исправлено:** график получил pointer events, `tabindex` и стрелки; строки таблицы и
пункты хронологии получили `tabindex`, `role="button"` и обработку Enter/Space;
добавлен `prefers-reduced-motion`.

### 3.9. Размер HTML можно уменьшить

Сейчас `report.html` ≈5 МБ: 109 JPEG-миниатюр (≈2,2 МБ base64), видео (≈1,5 МБ base64),
раскадровка и ключевые кадры. Для урока это терпимо, но можно:

* перейти на WebP/AVIF для миниатюр (экономия 30–50 %);
* не встраивать видео в HTML, а давать ссылку на `drop.mp4` (но тогда теряется
  автономность);
* отдавать раскадровку отдельным файлом, а не base64.

**Рекомендация:** оставить текущий вариант для автономности, но добавить «облегчённую»
сборку без видео для медленного интернета.

### 3.10. Нет тестов и CI

Нет ни одного автотеста: ни проверки, что `frames.csv` пересобирается, ни проверки
`params.json`, ни проверки, что HTML не содержит `@@...@@`.

**Рекомендация:** добавить `pytest`-тест на 3–5 инвариантов (f_hit в диапазоне,
e в диапазоне, g в диапазоне, отсутствие placeholders) и GitHub Actions.

```bash
python analysis/final_analysis.py   # печатает hit 1.643 s, apex 2.024 s, hit2 2.406 s

python analysis/make_html.py
python analysis/check_velocity.py
```

Ожидаемые значения:

* `g_fall ≈ 9.33`, `g_bounce ≈ 9.68`;
* `drop ≈ 181.5 см`, `rise ≈ 75.4 см`;
* `e_vel ≈ 0.630`, `e_h ≈ 0.645`;
* `f_hit ≈ 50.29`, `f_apex ≈ 61.73`, `f_hit2 ≈ 73.18`;
* в `report.html` нет строк `@@SCHOOL_...@@`;
